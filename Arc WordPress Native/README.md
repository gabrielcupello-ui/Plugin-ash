# Ash River Collective — WordPress Native Core (Option 3)

WordPress plugin that implements **Option 3**: **native storage and logic in MySQL**, with **connectors to Google Apps Script / Sheets** for progressive synchronization. This is the migration end state: data lives in WordPress, with optional Google sync.

## Summary

This plugin is the native core of Ash River Collective. It stores EOD reports, HR applications, and tasks in dedicated WordPress tables. Data can be progressively synchronized with Google Sheets through a queue (`arc_native_sync_queue`) and an Apps Script endpoint.

## Features

- **Native core**: dedicated tables for EOD, HR, Tasks, and Sync Queue.
- **Module registry**: `Arc_Native_Modules` lets you add/remove modules without touching the core.
- **Native dashboard** with shortcode `[arc_native_dashboard]`.
- **Google connector** via sync queue (`arc_native_sync_queue`) and an Apps Script endpoint.
- **Compatibility**: detects and reuses `arc-employee-time-clock` for the Time Clock module.
- **REST API**: `/wp-json/arc-native/v1/modules` and `/wp-json/arc-native/v1/stats`.
- **Tailwind CSS v4**: loaded via CDN on frontend and wp-admin.

## Installation

1. Copy the `arc-wordpress-native` folder to `wp-content/plugins/`.
2. Activate the plugin.
3. Create a page with the shortcode `[arc_native_dashboard]`.
4. Go to **ARC Native** in the side menu and configure:
   - Google Sync Bridge URL (Apps Script endpoint).
   - Shared API Secret.
   - Enable synchronization.

## Tailwind CSS

The plugin loads **Tailwind CSS v4** via CDN:

```html
<script src="https://cdn.jsdelivr.net/npm/@tailwindcss/browser@4"></script>
```

All templates (`dashboard.php`, `eod.php`, `time-clock.php`, `hr.php`, `tasks.php`) and the admin page use Tailwind utility classes. `assets/css/native.css` is empty (compatibility only) to avoid conflicts with the classes generated by the CDN.

## Architecture

```
WordPress User
        ↓
[arc_native_dashboard] / module shortcodes
        ↓
   Arc_Native_Core (REST + UI)
        ↓
Arc_Native_Modules + Arc_Native_Google_Bridge
        ↓
MySQL (arc_native_* tables)
        ↓
Sync queue → Google Apps Script / Sheets (optional)
```

Main components:

- `Arc_Native_Activator`: creates tables, flushes rewrite rules, and handles activation/deactivation.
- `Arc_Native_Modules`: module registration and ordering.
- `Arc_Native_Core`: shortcodes, REST routes, assets, admin UI.
- `Arc_Native_Google_Bridge`: sync queue with Google Apps Script.

## REST endpoints

Namespace: `/wp-json/arc-native/v1/`

| Route | Method | Description | Permissions |
|-------|--------|-------------|-------------|
| `/modules` | GET | Lists the registered modules. | Logged-in user |
| `/stats` | GET | Returns dashboard statistics. | Logged-in user |

Example response for `/stats`:

```json
{
  "week_hours": 32.5,
  "eod_count": 12,
  "active_tasks": 5,
  "candidates": 3
}
```

## Module registry (extension)

`Arc_Native_Modules` lets you add modules without modifying the core:

```php
add_action( 'arc_native_modules_init', function ( $registry ) {
    $registry->register( 'invoices', array(
        'label'         => 'Billing',
        'description'   => 'Invoice management',
        'icon'          => 'money-alt',
        'shortcode'     => 'arc_native_invoices',
        'order'         => 50,
        'capability'    => 'read',
        'google_sync'   => true,
    ) );
} );
```

The core will automatically look for `templates/invoices.php` to render the shortcode.

## Google sync

1. Deploy a Web App in Apps Script with `doPost` that receives JSON.
2. Paste the URL in **ARC Native > Google Sync Bridge URL**.
3. Every change that triggers `do_action( 'arc_native_record_changed', $module, $record_id, $action, $data )` is enqueued.
4. A cron every 5 minutes processes the queue and sends the changes to Google.

Body sent to Google:

```json
{
  "timestamp": 1700000000,
  "module": "eod",
  "record_id": 123,
  "action": "create",
  "payload": { "report_date": "2026-09-03", "hours_worked": 8.5 },
  "signature": "hmac-sha256"
}
```

Apps Script must verify the HMAC with the same secret configured in WordPress (or `wp_salt('auth')`).

## Hooks and filters

| Hook / Filter | Type | Description |
|---------------|------|-------------|
| `arc_native_modules_init` | action | Fires when the registry is built. Receives `Arc_Native_Modules`. |
| `arc_native_modules` | filter | Allows modifying the final module list. |
| `arc_native_dashboard_stats` | filter | Allows modifying dashboard statistics. |
| `arc_native_force_assets` | filter | Forces asset loading. |
| `arc_native_record_changed` | action | Fires when a record changes. Automatically enqueued by the bridge. |

## Time Clock integration

If the plugin `arc-employee-time-clock` is active, the dashboard uses its functions to calculate `week_hours`. Otherwise, the `time_clock` module is rendered with `templates/time-clock.php`.

To report hours to the dashboard:

```php
add_filter( 'arc_native_dashboard_stats', function ( $stats, $user_id ) {
    $stats['week_hours'] = 40; // calculate from your source.
    return $stats;
}, 10, 2 );
```

## Troubleshooting

| Symptom | Likely cause | Solution |
|---------|--------------|----------|
| Tables do not exist | Plugin activated without rewrite flush | Deactivate and reactivate the plugin. |
| Not syncing with Google | Sync disabled or empty URL | Check **ARC Native > Active sync** and URL. |
| Empty stats | Inactive modules or no data | Verify that the modules are registered and active. |
| Tailwind styles not applied | CDN not loaded | Verify connection to `cdn.jsdelivr.net`. |
